## 5. Fixes in this pass

See the commit "QA pass fixes". Each fix has a regression test.

- **QA-01** — refresh gets its own limiter (`auth-refresh`, configurable), and the admin app shares
  one in-flight refresh between parallel requests and ends the session only when the server says the
  refresh token is invalid (400/401), not on 429 or a network error.
- **QA-02** — the shell collapses the sidebar into an off-canvas menu below 900 px.
- **QA-03** — the honeypot is hidden with a clip instead of an offset.
- **QA-04** — refresh-token rotation is atomic: only one call can revoke a given token; a concurrent
  second use is treated as reuse.
- **QA-06** — the audit log records hard and soft deletes as `Deleted` with the entity's key values.

New configuration key: `Auth:RateLimit:Refresh` (`PermitLimit` 60, `Window` 00:01:00).

Regression tests: `AuthEndpointTests.Refresh_does_not_spend_the_login_budget`,
`AuthEndpointTests.Concurrent_refreshes_with_one_token_let_exactly_one_through`,
`AuditDeleteTests` (role hard delete, student soft delete); specs `auth.service.spec.ts` (one shared
refresh, 429 keeps the session, 400 ends it, adopting another tab's pair),
`auth.interceptor.spec.ts` (rate-limited refresh surfaces 429, not 401),
`public-registration.component.spec.ts` (honeypot inside the viewport, no sideways scroll, ar/en),
`shell.component.spec.ts` (drawer opens, closes from the backdrop and on navigation). One existing
spec was adjusted: "surfaces the original 401 when the refresh itself fails" simulated the failure
with a plain `Error`, which is now (correctly) a transient failure; it uses a server 400 instead.
The 390 px and Arabic checks were repeated in the browser after the fixes: no horizontal scroll on
the family, staff and public pages.

Verification: `dotnet build` 0 warnings / 0 errors; unit 117/117, integration 137/137;
`npm run build` OK; `npm test` 53/53.
